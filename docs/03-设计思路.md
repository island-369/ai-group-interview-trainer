# 03 · 设计思路

> 版本：v0.1 ｜ 日期：2026-10-24 ｜ 本文回答"为什么这样设计"，具体设计见 [04-设计方案](04-设计方案.md)。

## 1. 问题本质：这个产品难在哪

把 AI 群面陪练做成"N 个聊天机器人轮流说话"是容易的，但它会立刻失效——因为群面的本质不是聊天，而是**多人实时博弈**。三个真正的难点：

1. **行为拟真难**：真实群面里 80% 的得分差异来自行为（何时开口、怎么抢话、如何应对被打断），而非观点本身。LLM 默认行为是礼貌、倾听、不抢话——恰好是群面里"陪跑型"候选人的画像。**过度礼貌的 AI 会让练习完全失真。**
2. **动态调度难**：谁在什么时候说话、冷场怎么救、冲突怎么升级，是全局节奏问题，不可能靠每个 agent 各自为政策出来。
3. **评估可信难**：LLM 打分天然有"幻觉"和谄媚倾向（给用户打高分），没有证据约束的评分报告等于没有报告。

因此设计重心排序：**调度 > 行为 > 内容 > 界面**。

## 2. 六大设计原则

### 原则 1：拟人优先于聪明（行为真实 > 内容智能）

AI 候选人的 KPI 不是"说得比用户好"，而是"像真人候选人"。允许 AI 观点平庸、有口癖、会啰嗦、会固执——这些"缺陷"恰恰是练习素材。一个观点质量 0.6 但会抢话会施压的 AI，比一个观点质量 0.95 但永远谦让的 AI，训练价值高得多。
**落地**：人格卡包含行为参数（aggressiveness 等）与语言瑕疵参数；内容质量单独成参，默认不超过 0.8，地狱档才到 0.9。

### 原则 2：导演-演员分离（节奏集中，扮演分布）

群面的"戏剧结构"（冲突、结盟、转折、压力）由不发言的 Director 集中编排；每个 Candidate 只需演好自己的角色。
**为什么不是自由多智能体**：自由对话涌现出来的是"圆桌会议"，不是"竞争性面试"。集中导演换来三样东西：难度可参数化、节奏可调控、场次可复现（回归测试的前提）。

### 原则 3：无证据，不评分

每个维度的每个分数必须挂接转录原文引用；改进建议必须指向具体行为事件（"第 14 轮你被打断后 3 轮未再发言"），而非"建议加强沟通"。分数与证据矛盾时触发仲裁而不是取平均。
**落地**：评估 prompt 强制输出 `evidence[]`，无证据的评分直接判无效重评；用户对报告的信任是产品的生命线。

### 原则 4：难度是连续参数，档位只是预设

难度不做成三档开关，而是一组连续参数的函数（对手强度 × 抢话频率 × 剧情压力 × 节奏），四档预设只是参数组合的快捷方式。这保证了"压力脱敏训练"可以渐进调节——这正是 US-3 的诉求。

### 原则 5：反馈双循环

- **即时环（练中）**：教练模式的方向性提示（P1），解决"当场卡死"；
- **延迟环（练后）**：证据化报告 + 专项训练推荐，解决"下次更好"。
两环分离：练中不干扰沉浸，练后保证深度。

### 原则 6：成本感知设计

单场对局是几十次 LLM 调用的叠加，成本结构必须在架构期就定好：龙套角色用小模型、导演决策规则化（LLM 只做辅助判断）、上下文滚动摘要压缩、评估离线化（不占实时预算）。

## 3. 训练科学性依据

| 方法论 | 在产品中的映射 |
|--------|----------------|
| 刻意练习（定向补短板） | 专项训练模式（FR-11）；报告的弱项 → 推荐训练动作 |
| 反馈即时性原理 | 教练模式（FR-12）；报告生成 ≤60s |
| 系统 de-脱敏（压力免疫） | 难度连续可调：友善→标准→集火→压力面（地狱档） |
| 测量一致性（评分信度） | BARS 行为锚点 + temp=0 + 多次采样取中位数 |

产品的成功指标不是"AI 多逼真"，而是**用户下次真实群面的通过率与行为改变**——报告的"改进动作"必须可执行、可验证（下次对局自动对比该动作是否出现）。

## 4. 拟真度分级路线（L0 → L3）

拟真是渐进交付的，每级都有独立可发布的价值：

| 级别 | 能力 | 对应里程碑 | 验收信号 |
|------|------|-----------|----------|
| L0 | 轮流发言，内容贴题 | M0 骨架验证 | 走通全流程 |
| L1 | 意愿调度：AI 主动择机发言、频率分化、冷场救场 | M1（MVP） | 盲测能区分人格；无"报幕感" |
| L2 | 抢话与打断、剧情事件（冲突/结盟/集火/跑题）、难度参数全开 | M2 | 老用户报告"有压迫感" |
| L3 | 语音对局（语速、打断延迟、情绪） | M3 | 语音端到端延迟可接受 |

**判据**：M1 不追求 L2，避免把打断的复杂度提前拖进 MVP；但协议与状态机从第一天就为打断预留字段。

## 5. 关键权衡记录

| 权衡点 | 选择 | 代价与接受理由 |
|--------|------|----------------|
| 集中导演 vs 自由涌现 | 集中 | 牺牲一点不可预测性；换来可控、可复现、可调难度——对训练产品是必需品 |
| 单写者（同一时刻一个发言者）vs 真并发抢话 | 单写者 + 打断协议 | 文本形态下真并发只会造成消息流混乱；打断用协议化事件表达，L3 语音再演进 |
| 逐维度拆分评估 vs 一次全评 | 拆分（每调用 2 维度） | 调用次数×4；换评分稳定性与证据密度，离线可接受 |
| 文本 vs 语音先行 | 文本 | 排除最大工程风险，先验证核心价值假设（US-1/US-2 均可文本满足） |
| AI 内容质量上限封顶 0.8 | 封顶 | 放弃"AI 轧压用户"的炫技；训练场需要的是"可战胜的对手"，难度应来自行为压力而非内容碾压 |
| 自研编排 vs Agent 框架 | 自研轻量 | 放弃框架生态；核心逻辑高度定制且规模有限，可控性优先 |
