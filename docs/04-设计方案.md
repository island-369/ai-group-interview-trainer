## 2. 题库模块

### 2.1 题目 Schema

```yaml
id: q_2026_001
type: resource_allocation        # open_debate | ranking | resource_allocation | case_analysis | debate
industry: 互联网                  # 行业标签，影响材料风格
difficulty: 2                     # 1-3
title: 100 万创新预算的分配
material: |                       # 背景材料（READING 阶段展示）
  你们是某互联网公司的战略委员会。公司拿出 100 万预算支持内部创新，
  有 6 个候选项目（附各自预算申请、预期收益、风险等级……）。
requirement: |                    # 讨论任务
  25 分钟内达成一致：如何分配这笔预算？需给出分配方案及理由。
key_points:                       # 参考思路（评估与 AI 立场生成用）
  - 优秀解法通常先建立评估标准（ROI/战略价值/风险），再套标准排序
  - 常见陷阱：逐项目争论而不立标准；平均主义；忽略风险对冲
assessment_focus: [内容贡献, 逻辑结构, 领导影响]
time_limit: { reading: 240, opening: 60, discussion: 1500, summary: 180 }
tags: [预算分配, 决策, 无标准答案]
```

### 2.2 抽题策略

按（题型 × 行业 × 难度）过滤随机；同一用户近期已练题目降权（30% 概率回避）。P1 出题 Agent 生成候选题后进入**人工审核队列**，未过审不入正式题库。

## 3. 对局流程详细设计

### 3.1 阶段定义与超时处理

| 阶段 | 默认时长 | 规则要点 | 超时/异常处理 |
|------|----------|----------|----------------|
| BRIEFING | 60s | 面试官宣题+规则（含各阶段时长） | 固定文本+轻LLM生成 |
| READING | 3–5min | 用户看材料可记笔记（私密）；AI 并行生成立场笔记 | 可点"提前完成"；到点强制进入 |
| OPENING | 60s/人 | 固定顺序（用户可选位置，默认第 3 位）；每人限时陈述 | AI 严格限时；用户超时 15s 被面试官打断进入下一位 |
| DISCUSSION | 20–25min | 导演调度（§5.3）；过半与剩 5min 时面试官提醒 | 共识判定通过 or 时间到 → 收敛；用户长时间沉默触发冷场处理（点名/教练提示） |
| SUMMARY | 3min | 先开放 60s"争取总结"发言（拟真：抢总结本身是剧情点），导演综合意愿指定 1 人 | 被指定者拒绝（用户）则顺延；AI 必接 |
| CLOSING | 30s | 面试官收尾，转入 REVIEW | — |

### 3.2 用户离线/断线

- WS 断开：对局暂停计时（≤5min），AI 不推进依赖用户的决策；重连按 seq 补发消息；
- 超时未归：面试官宣布结束，评估正常进行（沉默本身就是评分素材）。

## 4. 消息协议（WS，JSON）

### 4.1 下行（服务器 → 客户端）

```jsonc
// 阶段流转
{"type":"phase","phase":"DISCUSSION","remain_sec":1500,"seq":41}
// AI 发言（流式，多段；段间为可打断窗口）
{"type":"speak_start","agent":"c_002","seq":42}
{"type":"speak_chunk","agent":"c_002","seq":42,"chunk":"我不同意刚才的标准，"}
{"type":"speak_end","agent":"c_002","seq":42,"interrupted":false}
// 打断事件（L2）
{"type":"interrupt","by":"c_005","target":"c_002","seq":43}
// 面试官/系统
{"type":"interviewer","text":"时间过半，请尽快收敛","seq":44}
// 教练提示（P1，仅用户可见）
{"type":"coach","hint":"现在没人控时间，适合你来推进收敛","seq":45}
```

### 4.2 上行（客户端 → 服务器）

```jsonc
{"type":"user_ready"}
{"type":"user_typing","on":true}            // 触发用户保护窗口
{"type":"user_speak","text":"..."}          // 文本MVP：整句提交
{"type":"user_note","text":"..."}           // 私密笔记
```

协议为 L2/L3 预留：`user_speak_start/chunk/end`（语音与长发言流式）、`interrupt` 双向化。所有下行消息持久化到 messages 表（seq 单调递增）。

## 5. 智能体详细设计

### 5.1 CandidateAgent：人格卡

```yaml
id: c_002
name: 陈锐
profile: { school: 某财经院校硕士研一, major: 金融, target: 咨询/战略 }
mbti: ENTJ
# ── 行为参数（0-1，导演调度输入；难度系统整体缩放）──
params:
  aggressiveness: 0.85     # 抢话/打断/主动发言冲动
  content_quality: 0.75    # 观点逻辑深度（有内容质量上限策略约束）
  cooperativeness: 0.30    # 附和/结盟倾向（低=习惯性反对）
  verbosity: 0.70          # 发言长度偏好（映射目标字数区间）
  composure: 0.80          # 被反驳/打断后的稳定性（影响是否情绪化）
  initiative: 0.75         # 立框架/推进议程倾向
# ── 语言风格 ──
speech_style:
  patterns: ["第一…第二…第三…", "回归本质看", "数据说话"]
  quirks: 语速快，句子偏短，偶带轻微攻击性反问
  avoid: [书面腔, 完美礼貌]
# ── 立场与专长（读题后由 LLM 生成快照）──
stance_seed: null          # READING 阶段填充：本题我的初始立场与论据
```

人格卡库内置 10+ 张模板（强势型/框架型/附和型/数据型/沉默型/搅局型/老好人型…），创建对局时按难度档的多样性要求抽组，参数按档位缩放后快照进 session_members。

**Prompt 结构（四层分离，便于回归测试）**：

```
[1 系统层] 人格卡全文 + "你是真实候选人，不是AI助手；允许不完美、允许固执"
[2 对局层] 题目材料 + 我的立场笔记 + 当前阶段与规则
[3 上下文层] 讨论纪要(滚动摘要) + 近K轮原文 + 剧情任务(如有)
[4 任务层] 本次任务：回应X/陈述立场/抢话后第一句… + 输出约束(目标字数、风格、只输出台词)
```

### 5.2 InterviewerAgent

职责：宣题、阶段转换宣告、时间提醒（过半/剩5min）、冷场干预、SUMMARY 指定、压力面（地狱档：质疑式追问"你刚才的方案数据在哪？"）。行为参数仅 `pressure` 一档（off/normal/stress），影响干预频率与语气。

### 5.3 DirectorAgent：调度与剧情（核心算法）

**发言意愿公式**（每决策窗口对每个空闲 agent 计算）：

```
desire = 0.35·aggressiveness                    # 人格基线
       + 0.25·topic_affinity                    # 当前议题与其立场相关度（小模型打分 0-1）
       + 0.20·provocation                       # 被点名/被反驳后的回应冲动（事件触发，指数衰减）
       + 0.15·silence_pressure                  # 自己连续未发言轮数压力
       − 0.15·recency_fatigue                   # 刚发言过的疲劳衰减
       ± scenario_modifier                      # 剧情事件强制项（如"集火用户"则+0.4）
desire ∈ [0,1]，加入 ±0.05 高斯扰动避免机械
```

**调度决策**：

```
top1, top2 = 按desire排序前二
if max_desire < 0.25 持续 ≥ 冷场容忍秒数(难度参数 pace, 8-25s):
    冷场处理 → 面试官推进议题 / 点名沉默最久者 / 剧情救场（三选一，带优先级）
elif |desire(top1) − desire(top2)| < 0.07 且 aggressiveness(top1/top2) 均高:
    抢话竞争 → 意志对抗：胜者发言，败者获得 provocation+0.5（憋着下次爆发）
else:
    top1 发言（流式）
```

**打断机制（L2，段间可打断窗口）**：

```
发言分 2–4 段输出，每段结束是窗口（600ms）：
  interrupt_desire_j = aggressiveness_j × conflict(current_speech, stance_j) × 0.8
  若某 j 的 interrupt_desire_j > 0.6：
    ① 当前发言者按 assertiveness 掷骰：坚持（压缩加速讲完）/ 让出（"好你说"）
    ② 打断者获得发言权，messages 记录 interrupt 事件
    ③ 被打断者获得 provocation +0.4（其人格决定是夺回还是记仇后发难）
用户发言同样可被抢话（仅拟真/地狱档），构成压力训练
```

**剧情引擎（剧本 = 事件队列 + 触发条件）**：开局按难度生成 2–5 个事件塞入队列，运行中满足条件即触发：

| 事件 | 触发条件 | 效果 |
|------|----------|------|
| 冲突升级 | 两 AI 立场对立且均已发言≥2次 | 双方 scenario_modifier 拉高，指定回合正面交锋 |
| 结盟 | 附和型 AI 存在 | 跟随多数派/强者，引用其观点 |
| 集火用户 | 地狱档 or 用户表现强势（发言占比>30%） | 2 个 AI 联合质疑用户最近观点 |
| 跑题 | 讨论中后段共识进度低 | 搅局型 AI 故意引偏（考察用户纠偏能力） |
| 时间压力 | 剩时<30% 且未收敛 | 面试官加压提醒；AI 开始急促短发言 |
| 抢总结 | SUMMARY 进入 | 多个高 initiative AI 竞争总结资格 |

**共识判定**：每 5 轮由小模型对"当前讨论与题目要求的收敛程度"打分（0–1），≥0.8 且剩时<40% 可提前进入 SUMMARY；到时强制进入。

### 5.4 EvaluatorAgent 与 CoachAgent

评估算法见 §6。CoachAgent（P1）：触发器 =（a）用户沉默 > 冷场容忍（b）用户连续 2 次发言长度 < 阈值（c）用户被抢话后 3 轮未再发言；提示生成约束为**方向性一句话**（"现在适合做时间提醒"），不代写话术，每日/每场限次（3 条），报告中统计提示依赖度。

## 6. 评估与报告设计

### 6.1 评分 Rubric（BARS 锚定，节选完整结构）

每维度 1–5 分（0.5 步进）。示例两维度完整锚点：

**维度 3 · 沟通表达**

| 分 | 行为锚点 |
|----|----------|
| 5 | 表达精炼有感染力；善用数字/类比；几乎无冗余；语速节奏与内容匹配 |
| 4 | 清晰流畅，重点突出，偶有啰嗦但可自我收敛 |
| 3 | 能说清观点，但平淡或有明显冗余重复 |
| 2 | 啰嗦、口头语多，重点模糊，需要他人追问才能明白 |
| 1 | 表达混乱无法理解，或长期沉默仅有只言片语 |

**维度 7 · 情绪抗压**

| 分 | 行为锚点 |
|----|----------|
| 5 | 被集火/打断时冷静拆解对方观点，据理力争不失风度，甚至化压力为说服力 |
| 4 | 面对反对保持平稳，能回应不慌乱 |
| 3 | 基本平稳，偶有急躁用语但未失控 |
| 2 | 被反驳后语无伦次、音量/攻击性明显升高，或明显退缩 |
| 1 | 被反驳后情绪化攻击他人，或彻底沉默退出讨论 |

其余 6 维度锚点结构相同（入库 `rubrics.yaml`，prompt 注入当前评分维度的锚点表）。

### 6.2 评估管线

```
① 行为切分：转录 → 事件序列（发言轮次、打断、沉默、引用、反驳、推进…）
   （规则可判的用规则：字数、沉默、被打断；语义的用小模型标注：引用/反驳/框架）
② 逐维度评分：9 次调用（8 维度 + 逐句标注），每次 2 个维度；
   输入 = 完整转录 + 行为事件表 + 该维度锚点 + 用户人格信息（可选：目标岗位）
   输出 = { dimension, score, evidence:[{quote, event_ref, why}], level_rationale }
   约束：temp=0；evidence 为空 → 该次无效重评（最多 2 次）；采样 3 次取中位数
③ 仲裁：3 次采样极差 >1 分的维度 → 第四次仲裁调用（附分歧样本）取仲裁值
④ 汇总：加权总分（权重默认均等，可按目标岗位预设）；
   相对名次 = 与本场 AI 各维度对比（AI 用简化评分：导演日志+转录同管线跑）
```

### 6.3 报告结构

```
复盘报告
├─ 总览：总分、名次（本场第 X/7）、一句话诊断、本场题目与配置
├─ 雷达图：8 维度（叠加本场 AI 平均与"校招通过线"参考带）
├─ 维度详情 × 8：分数 + 等级评语 + 证据引用（原话高亮，含轮次）
├─ 逐句标注回放：转录时间轴，加分句(绿)/减分句(红)/关键事件(打断/沉默)标记
├─ 优势 TOP2 / 短板 TOP2（各附证据）
├─ 改进动作 × 3：具体到行为（"下一次，当讨论过半未立标准时，主动提出评估框架"）
│   并挂接专项训练入口（FR-11）
└─ 附录：AI 对手人格卡回顾、导演日志摘要（"第 14 轮集火你的原因"）
```

## 9. 关键时序：用户发言后发生了什么

```
1. 用户提交 user_speak → SessionManager 写 messages(seq=n)
2. 广播 user_speak 确认；启动导演决策定时器（0.8–2.5s 随机）
3. 导演窗口到：计算各 AI desire（含对用户发言的 provocation 响应）
4. 选定发言者 → 其 Agent 组装四层 prompt（含滚动摘要+近K轮）
   → LLM Gateway 流式调用（首token≤1.5s）
5. speak_chunk 持续推送；段间窗口检查 interrupt_desire
6. speak_end → 写 messages(seq=n+1) → 回到步骤 2 循环
   （每 5 轮穿插：剧情条件检查、共识打分、纪要滚动更新）
```
