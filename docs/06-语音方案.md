# 06 · 语音方案（路线 A：级联管线）

> 版本：v1.0 ｜ 日期：2026-10-25 ｜ 上游：[02-系统架构](02-系统架构.md)、[04-设计方案](04-设计方案.md)、[05-实现方案](05-实现方案.md)
> 结论：**语音只是给现有对局"加一层壳"**——导演调度、人格卡、评估管线全部原样复用，新增一个"语音网关"层。

## 1. 路线决策

### 1.1 级联管线 vs 端到端语音大模型

| | A. 级联（本方案） | B. 端到端（豆包 Realtime / Qwen3-Omni / GLM-Realtime） |
|---|---|---|
| 延迟 | 1.0–2.5s（满足 NFR <2.5s） | ~300ms |
| 导演调度 | **完整保留**（调度权在我们手里） | 丢失——模型自控轮替，无法做意愿调度/剧情 |
| 人格一致性 | 强（文本 LLM 扮演，已验证） | 弱（5 人格共用一个语音模型，人设漂移） |
| 评估管线 | 自动产转录，零改动 | 仍需转写，反而多一步 |
| 成本 | 低（LLM 不变 + TTS 按字符） | 高 |
| 模型可替换 | 每层独立可换 | 供应商锁定 |

端到端唯一优势是延迟与韵律，作为 V3 对照实验保留；产品基座用级联。

### 1.2 V1 组件选型（默认项，全部可经 resolver 层翻转）

| 组件 | V1 默认 | 备选/升级路径 |
|------|---------|----------------|
| 流式 ASR | **sherpa-onnx 本地流式**（pip 即用，Mac M 系列 CPU RTF≈0.1，零账号零成本） | 火山豆包流式 ASR API / 阿里百炼 Paraformer（规模化后换，只改 asr.py） |
| 流式 TTS | **edge-tts**（免费零账号，20+ 中文音色，支持语速/音调参数——正好喂人格参数映射；非官方接口为已知风险，见 §7） | MiniMax Speech 2.6（情绪标签）/ 火山豆包 TTS（音质标杆）/ 本地 CosyVoice3+云 GPU（克隆，V2） |
| VAD/断句 | sherpa-onnx VAD（与 ASR 同库） | TEN-VAD |
| 音频传输 | 独立 WebSocket `/ws/voice/{session_id}`（与事件 WS 分离，规避二进制/JSON 混流） | 全双工阶段换 WebRTC（LiveKit） |

**关键简化**：全场只有用户一个真人说话，**不需要说话人分离（diarization）**——多人语音里最难的活在我们的场景天然不存在。

## 2. 总架构

```
浏览器                                            服务端（FastAPI）
┌────────────────────┐   事件WS(现有,不变)      ┌───────────────────────────┐
│ room.html(语音模式) │ ◀────────────────────▶ │  SessionRuntime(完全不变)   │
│  字幕气泡/阶段条     │                        │  导演/Agent/评估            │
│                    │                        └──────────▲────────────────┘
│  AudioWorklet 采集  │                                     │ 订阅广播队列(现有 _subs)
│  48k→16k PCM 分片  │   语音WS /ws/voice/{sid}             │
│  播放队列(WebAudio) │ ───────用户PCM(半双工门控)──▶ ┌──────┴─────────┐
│                    │ ◀──────TTS音频分片────────── │  VoiceGateway   │
└────────────────────┘                             │ VAD → 流式ASR    │
                                                   │  ↓ 终稿文本       │
                                                   │  → handle_user(  │
                                                   │    user_speak)   │
                                                   │ 句缓冲 → TTS(按   │
                                                   │ 人格音色) → 分片   │
                                                   └─────────────────┘
```

数据流：
- **上行**：浏览器 AudioWorklet 采集 16kHz PCM 100ms 分片 → 语音 WS → VAD 端点检测（用户说完）→ 流式 ASR 终稿文本 → **作为现有 `user_speak` 消息直接进入 handle_user**（输入路径零改动）；
- **下行**：VoiceGateway 订阅会话广播队列（现有 `_subs` 机制），缓冲 `speak_chunk` 到句边界（。！？；首句遇"，"也切，压首包）→ 按该 agent 音色流式 TTS → `audio` 分片推给浏览器 → 播放队列顺序播放；**文字字幕照常显示**（评估/回放/弱网兜底全保留）。

## 3. 交互设计：半双工 + 按键抢话

| 状态 | 麦克风 | AI 语音 | 说明 |
|------|--------|---------|------|
| 空闲 | 开（VAD 监听） | 静音 | 你可随时开口 |
| AI 发言中 | 关 | 播放中 | 无回声回路，不需要 AEC |
| 按住抢话键 | **立即开** | **立即停** | 发 `user_barge`：服务端取消当前 LLM 生成 + 清空 TTS 队列 + 广播 `interrupt` 事件（M2 打断协议的事件，V1 行为=被抢者让出；M2 接上"坚持/让出"人格判定） |

朗读（READING）阶段做笔记仍用文字框；个人陈述/讨论/总结全部语音输入。**文字输入框保留**——识别失败、嘈杂环境、引用数字时的兜底。

## 4. 音色系统（对局内固定，跨局随机）

```
configs/voices.yaml
  - id: v_young_male_01        # 音色池条目（V1: edge-tts 音色名）
    provider_voice: zh-CN-YunxiNeural
    tags: [年轻, 男, 中性]       # 气质标签，供人格过滤
    base_rate: +0%             # 基准语速/音调
    base_pitch: +0Hz

解析流程（创建对局时，session rng_seed 驱动）：
  persona.archetype ──▶ 按 tags 过滤音色池（强势型→[果断/低沉]，附和型→[温和/柔]…）
        │
  seeded rng 抽 1 个 ──▶ 参数微扰叠加人格映射：
        │                 rate = base + (verbosity−.5)×30% + (aggressiveness−.5)×20%
        ▼                 pitch 同理（composure 影响播放时动态微调，V2）
  voice = {provider_voice, rate, pitch} ──▶ 快照进 session_members.persona.voice
```

- **对局内**：音色绑定成员不变（身份锚点）；**跨局**：新 seed 重新抽——"每局都是陌生对手"。
- 快照进 persona JSON → 断线重连/回放/回归测试全部可复现。
- 面试官单独 2–3 个专业音色池。地狱档倾向压迫感音色（难度表达的一部分）。
- V2 增强：零样本克隆扩充音色池（**只用有授权的参考音频**，合规红线）。

## 5. 延迟预算（V1 目标 ≤2.2s）

| 环节 | 预算 | 手段 |
|------|------|------|
| VAD 端点判定 | 300–500ms | 自定义静音窗 450ms |
| ASR 终稿 | ~100–300ms | 流式_partial 已就绪，端点后只差 last frame |
| LLM 首句 | 300–800ms | deepseek-flash 快；首句短切（遇逗号即断） |
| TTS 首包 | 300–600ms | edge-tts 流式，按句合成（1–4s/句） |
| **合计** | **1.0–2.2s** | 满足 02§5 NFR（<2.5s） |

## 7. 成本与风险

**成本**：V1 除 LLM 外零现金成本（本地 ASR + edge-tts 免费）。一场语音对局 LLM 成本与文字场相同（约几毛）。换商用 TTS 后约 +0.5–3 元/场（按 7k 字符）。

| 风险 | 等级 | 应对 |
|------|------|------|
| edge-tts 非官方接口被微软封禁 | 中 | resolver 抽象已隔离，切换 MiniMax/火山只改一个文件；观察期内不建议商用发布依赖它 |
| ASR 与 uvicorn 同进程抢 CPU | 中 | ASR/VAD 跑独立线程池（GIL 释放的 ONNX 推理），必要时独立进程 |
| 首句延迟波动 | 中 | 首句逗号即断 + TTS 分片缓存预热 |
| 浏览器自动播放限制 | 低 | 现有"准备开始"点击流程天然满足 AudioContext resume |
| 回声/嘈杂环境误触发 | 低 | 半双工门控天然免疫；VAD 能量阈值兜底 |
| 克隆音色合规（V2） | — | 只用有授权/自制参考音频，池子入库登记来源 |

## 8. 与既有路线的关系

- **M2（文字版打断/剧情）**：语音 V1 先行；`user_barge` 已按 M2 的 `interrupt` 事件协议发出，M2 落地"坚持/让出"人格判定后语音端直接继承——**不做两遍**。
- **评估**：语音场自动产转录，评估管线零改动；语速/填充词/音量等副语言维度留 P2（转录里已有时间戳可算语速）。
- **回放**：audio 不落库（V1 只存转录），回放按现有文字转录 + 可选 TTS 重合成。

## 9. 实施记录（V1.0–V1.4，2026-10-25）

**已交付**：V1.0 冒烟（TTS→ASR 回环 96% 字符命中）✅；V1.1 音色池+seed 抽签+人格参数映射（6 测试）✅；V1.2 语音 WS+VAD+ASR+前端采集播放 ✅；V1.3 VoiceBridge（句切分/首句短切/字幕同步）✅；V1.4 抢话（取消生成+部分文本落库+interrupt 事件，含单测）✅。全链路脚本验证通过（模拟麦克风走完整场：用户语音→VAD→ASR→进对局→AI 语音回放，36 项 pytest 全绿）。V1.5 真人试听待用户执行。

**实施中的关键修正（与 §2 初稿的差异）**：
1. **麦克风门控归客户端**：服务端不得按"合成队列状态"丢帧——宣题长文本的合成积压会落后于对局进度，把用户有效帧全部误杀。客户端按自己的播放队列闭麦（`micAllowed()`）即是正确的半双工门控。
2. **跨阶段过期语音清队**：phase 事件触发 bridge 清空待合成队列（含在飞合成），语音滞后被限定在一个阶段内，不会越积越多。
3. **ASR 与 WS 接收循环解耦**：识别走 worker 队列（`asyncio.to_thread`），接收循环只入队——否则突发帧+慢识别会灌满 uvicorn 的 ws 消息队列，触发传输层暂停读、连 pong 都被暂停，客户端 keepalive 超时。
4. **VAD `min_silence=0.7s`**：合并句中逗号停顿（~0.5s），整句一次性出段；用户语音帧尾需 ≥0.9s 静音才触发端点。
5. **edge-tts 限流实测**：高频调用（当日数百句）后出现空音频（<1KB/句），属微软侧节流；开发验证够用，**商用前必须换 MiniMax/火山或自托管**（resolver 已隔离，换 provider 只改 tts 文件）。
