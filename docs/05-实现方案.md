## 1. 技术选型

| 层 | 选型 | 理由 | 备选 |
|----|------|------|------|
| 后端 | Python 3.11 + FastAPI | asyncio 原生适合多 agent 并发与 WS；LLM 生态最成熟 | Node.js/NestJS |
| 实时通道 | FastAPI WebSocket + asyncio TaskGroup | 单进程多对局；Session Runtime 天然映射协程组 | Socket.IO（多一层抽象暂不需要） |
| LLM 访问 | OpenAI 兼容 SDK + 自研 Gateway 薄层 | 主模型可切换（GLM-4 系/GPT/DeepSeek 等）；流式/重试/降级统一 | LangChain（过重，放弃） |
| 前端 | Next.js 14 + React + TailwindCSS + Zustand | SSR 快速开发；组件生态全；Zustand 轻量契合 seq 追加模型 | Vite+React |
| 图表 | ECharts（雷达/曲线） | 雷达图与时间轴成熟 | — |
| 数据库 | SQLite（SQLAlchemy ORM）→ PostgreSQL | 同一套 ORM，切换零成本 | — |
| 后台任务 | Arq（Redis）或 FastAPI BackgroundTasks（MVP） | 评估离线化 | Celery |
| 配置 | YAML（人格卡/难度档/rubric/题目） | 非工程师可编辑；版本管理 | DB 配置表 |
| 部署 | Docker Compose | 单机起步 | K8s（多机阶段） |
| 测试 | pytest + pytest-asyncio + Playwright | 单元/E2E | — |

**模型分层策略**（Gateway 路由规则）：
- 强模型（主模型）：用户交互的 Candidate、Interviewer、Evaluator
- 轻模型：龙套 Candidate、导演辅助判断（话题相关度/共识打分）、Coach、行为语义标注

## 3. 数据库表设计（核心 DDL 摘要）

```sql
CREATE TABLE users (
  id TEXT PRIMARY KEY, anon_token TEXT UNIQUE, created_at TIMESTAMP
);

CREATE TABLE questions (
  id TEXT PRIMARY KEY, type TEXT NOT NULL, industry TEXT, difficulty INT,
  title TEXT NOT NULL, material TEXT, requirement TEXT,
  key_points JSON, assessment_focus JSON, time_limit JSON, tags JSON,
  status TEXT DEFAULT 'approved', created_at TIMESTAMP
);

CREATE TABLE sessions (
  id TEXT PRIMARY KEY, user_id TEXT NOT NULL, question_id TEXT NOT NULL,
  config JSON NOT NULL,            -- 难度参数快照/人格组合/AI数/时长
  phase TEXT NOT NULL, status TEXT NOT NULL,   -- running/finished/aborted
  started_at TIMESTAMP, ended_at TIMESTAMP
);

CREATE TABLE session_members (
  session_id TEXT NOT NULL, member_id TEXT NOT NULL,
  role TEXT NOT NULL,              -- user / candidate / interviewer / director(不落库可)
  persona JSON,                    -- 人格卡实例化快照（参数已按难度缩放）
  display_name TEXT, PRIMARY KEY (session_id, member_id)
);

CREATE TABLE messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL, seq INTEGER NOT NULL,
  speaker_id TEXT, kind TEXT NOT NULL,   -- speak/interrupt/phase/system/coach
  text TEXT, ts TIMESTAMP NOT NULL, meta JSON,  -- interrupted_by/duration_ms/desire...
  UNIQUE (session_id, seq)
);

CREATE TABLE director_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL, turn INT NOT NULL,
  decision JSON NOT NULL,          -- {desires:{...}, chosen, reason, drama_event}
  ts TIMESTAMP NOT NULL
);

CREATE TABLE reports (
  session_id TEXT PRIMARY KEY,
  overall REAL, rank INT, radar JSON, strengths JSON, weaknesses JSON,
  actions JSON, sentence_marks JSON, raw JSON, created_at TIMESTAMP
);

CREATE TABLE score_details (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL, dimension TEXT NOT NULL,
  score REAL NOT NULL, samples JSON, evidence JSON,
  UNIQUE (session_id, dimension)
);

CREATE TABLE training_records (     -- 成长曲线时序
  user_id TEXT NOT NULL, session_id TEXT NOT NULL,
  dimension TEXT NOT NULL, score REAL NOT NULL, ts TIMESTAMP,
  PRIMARY KEY (session_id, dimension)
);
```

## 4. 核心实现要点

### 4.1 对局运行时（每场一个协程组）

```python
async def run_session(session):
    async with asyncio.TaskGroup() as tg:
        tg.create_task(phase_timer(session))        # 阶段计时与流转
        tg.create_task(director_loop(session))      # 调度循环（§4.2）
        tg.create_task(side_tasks(session))         # 纪要更新/共识打分/剧情检查（旁路）
        # agent 生成任务按需在 director_loop 中 spawn
```

- WS 断开 ≠ 对局终止：Session Runtime 与连接解耦，重连按 seq 补发；
- 进程内 `session_registry` 管理活跃对局；重启恢复：从 DB 读 messages + config 重建状态（MVP 重启即挂起，提示用户重开，M2 补恢复）。

### 4.2 导演循环骨架

```python
async def director_loop(s):
    while s.phase != CLOSING:
        await wait_speech_settle(s)                 # 等上一发言结束
        await asyncio.sleep(jitter(0.8, 2.5))
        if s.phase == OPENING:  await next_in_order(s); continue
        if s.phase == DISCUSSION:
            if s.user_typing and protect_user(s): continue
            desires = {a.id: desire(a, s) for a in s.idle_candidates()}
            top = ranked(desires)
            if top[0].score < COLD_FLOOR and s.idle_for > s.pace:
                await handle_coldfield(s)           # 面试官推进/点名/剧情
            elif near(top[0], top[1]) and both_aggressive(top):
                await resolve_speech_race(s, top)   # 抢话竞争
            else:
                await speak(s, top[0].agent)        # 流式+段间打断窗口
            maybe_fire_drama(s); log_decision(s)
```

### 4.3 LLM Gateway

- 统一 `complete(role="strong|light", messages, stream, json_schema)`；按 role 路由到配置的模型；
- 流式转发 + 首包超时 1.5s（超则重试/降级 light 模型）；
- 重试：429/5xx 指数退避 ×2；JSON 输出失败重试 ×2 后走修复 prompt；
- 预算熔断：session 级 token 计数，超预算降级 light 模型，超硬顶终止对局（面试官话术收尾）。

### 4.4 上下文管理（成本关键路径）

- 各 Candidate 上下文 = 题目 + 自己立场笔记 + **讨论纪要**（每 5 轮旁路任务用轻模型更新，≤400 tok）+ **近 K=8 轮原文** + 剧情任务；
- 总量控制在 ~2k tok/次调用；Evaluator 用完整转录（离线，无实时约束）；
- 纪要更新条件触发：新共识/新论点/阶段事件，非每轮全量重写。

### 4.5 评估管线实现

- 管线 = 9 个可并发调用（8 维度 + 逐句标注），`asyncio.gather` + JSON Schema 约束输出；
- 采样 3 次：同 prompt 重放（temp=0 下靠 few-shot 顺序扰动产生差异）；极差>1 触发仲裁调用；
- 逐句标注输出 `{seq, mark: positive|negative|neutral|event, reason}`，直接驱动前端回放高亮；
- 报告生成 ≤60s：并发后实测预期 20–40s，超时降级（先出雷达+总分，标注异步补齐）。

### 4.6 配置系统

`configs/*.yaml` 启动加载 + 热重载（开发期）；人格卡与难度参数在创建对局时**快照进 session.config/persona**，运行中改配置不影响进行中对局（回归测试的前提）。

## 5. 里程碑计划

| 里程碑 | 周期 | 范围 | 验收标准 |
|--------|------|------|----------|
| **M0 骨架** | 第 1 周 | monorepo 初始化、CI、LLM Gateway、WS hello、题库 schema+10 题、人格卡 5 张 | 单 AI 对话流式跑通；配置加载测试通过 |
| **M1 文本 MVP（L1）** | 第 2–4 周 | 六阶段完整流程、意愿调度（无打断）、对局室 UI、8 维报告+雷达、训练配置 | 一场 6 人对局（5 AI）完整走通；盲测能分人格；报告证据完备率 100%；NFR 性能达标 |
| **M2 拟真化（L2）** | 第 5–7 周 | 段间打断、剧情引擎、四档难度、专项训练、教练模式、逐句标注回放、AI 名次 | 地狱档老用户压迫感可用性访谈确认；打断事件协议全链路（含用户被抢话）；回归测试集建立 |
| **M3 语音与成长** | 第 8 周+ | ASR/TTS 语音对局、成长曲线、题库 50+、断线恢复、PostgreSQL 切换 | 语音端到端延迟可接受（<2.5s）；曲线数据准确 |
| 远期 | — | 多真人混合、面试官视角回放、机构版 | 按市场反馈排期 |

每期结束做一次固定剧本回归回放（见 §6），防止 prompt 调整造成拟真度退化。

## 6. 测试与质量策略

| 类型 | 方法 | 关键指标 |
|------|------|----------|
| 单元测试 | desire 公式、状态机迁移、打断协议、配置缩放（pytest） | 覆盖核心模块 ≥85% |
| Prompt 回归 | 固定题目+人格+随机种子 → 固定脚本驱动 → 断言关键行为（某轮必抢话/冷场必救场），基于 director_logs | 回归集 20 场剧本；行为通过率不回退 |
| 评估器一致性 | 同一转录跑 5 遍全管线 | 各维度分方差 <0.3；证据完备率 100% |
| E2E | Playwright + 脚本用户（定时发言的机器人账号）打完整场 | 全流程无人工干预通过 |
| 负载 | 单进程 5 并发对局 | 首包延迟 P95 达标 |

## 7. 成本估算（单场文本对局）

场景：5 AI + 用户，讨论 25 分钟，约 70 次 AI 发言。

| 项 | 估算 |
|----|------|
| Candidate 调用 | 输入 ~2k tok × 70 ≈ 140k；输出 ~300 tok × 70 ≈ 21k |
| 导演辅助（轻模型） | 意愿打分/共识，≈ 20k tok |
| 面试官+剧情 | ≈ 10k tok |
| 评估管线（离线，强模型） | 转录 ~18k × (9 任务 × 3 采样) ≈ 500k tok（**大头**） |
| **合计** | 约 70 万 tok/场；按国产主流模型定价约 **¥0.5–2/场** |

优化路径：评估采样降为 2 次（方差达标前提下）、龙套走轻模型、逐句标注降频。目标长期 ≤¥1/场。

## 8. 风险清单

| 风险 | 等级 | 应对 |
|------|------|------|
| AI 过度礼貌，拟真失真 | 高 | 人格卡行为参数 + 剧情强制冲突 + prompt"你不是助手"层；回归测试盯行为 |
| 抢话并发搞乱消息流 | 高 | 单写者原则 + 协议化打断（02§3.2），L2 才开 |
| 评分不稳定/谄媚高分 | 中高 | BARS 锚定 + temp=0 + 采样中位数 + 证据强制 + 仲裁 |
| 长讨论上下文超限/成本爆炸 | 中 | 滚动摘要 + 近 K 轮原文 + 预算熔断（¥2 硬顶） |
| 用户沉默导致对局停滞 | 中 | 冷场处理三选一 + 教练提示 + 面试官点名 |
| LLM 服务不可用 | 中 | Gateway 多供应商切换 + 降级话术（面试官宣布暂停） |
| 语音复杂度超预期（M3） | 中 | 严格后置；若延迟不达标维持文本并重排期 |
